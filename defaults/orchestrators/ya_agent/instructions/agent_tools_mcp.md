# Инструменты и MCP-интеграции

Эта инструкция описывает, как проектировать инструментальные возможности агентов Yandex AI Studio. Используйте её вместе с инструкцией по Responses API (`agents_responses_api`) и справочником моделей (`yandex_models_reference`).

## Встроенные инструменты агентов

Агенты могут автоматически вызывать инструменты для получения информации или выполнения действий. В AI Studio доступны:

- **File Search Tool** - RAG: поиск по вашим файлам (базе знаний) через Vector Store API или Files API.
- **Web Search Tool** - поиск в интернете через поисковую базу Яндекса.
- **Image Generation Tool** - генерация изображений по текстовому описанию; работает через Responses API с любыми текстовыми моделями; модель сама решает, когда вызвать инструмент.
- **MCP Tool** - подключение к MCP-серверам для работы со сторонними API.
- **Code Interpreter** - написание, воспроизведение и отладка Python-кода в виртуальной тестовой среде; поддерживает сохранение состояния, работу с файлами и визуализацию. Подходит для проверки и преобразования данных.

## Кастомные функции (function calling)

Функции описываются в `tools` Responses API как FunctionTool:
- `type` - всегда `function`;
- `name` - имя функции;
- `description` - описание, на основе которого модель решает, вызывать ли функцию;
- `parameters` - JSON Schema параметров;
- `strict` - строгая валидация параметров (по умолчанию `true`);
- `defer_loading` - отложенная загрузка функции через tool search (полезно при большом количестве функций).

Результат вызова возвращается модели как `function_call_output` с полем `call_id`.

## Code Interpreter

- Вызов: `code_interpreter` как инструмент в `tools`.
- Ответ модели - `code_interpreter_call` с полями `code`, `container_id`, `outputs` (логи или изображения).
- Среда сохраняет состояние между вызовами (контейнер); есть работа с файлами и визуализацией.
- Лимиты: 3 одновременных запуска Code Interpreter на облако; таймаут выполнения кода в контейнере - 20 минут; таймаут жизни контейнера - 20 минут.
- Подходит для анализа CSV/JSON, вычислений, генерации графиков.

## MCP Hub

MCP Hub - функциональность AI Studio для создания, управления и мониторинга MCP-серверов: подключение внешних MCP-серверов и создание собственных (с нуля или из шаблонов).

### Сценарии использования

- Подключение моделей к CRM, ERP-системам или внутренним хранилищам.
- Автоматизация бизнес-процессов.
- Специализированные AI-ассистенты (юридические, медицинские, технические).
- Интеграция с внешними API (новости, курсы валют).

### Транспортные механизмы MCP

- **Streamable HTTP** - современный актуальный механизм: агент получает обновления без постоянного HTTP-соединения.
- **HTTP with SSE** - устаревший: одно постоянное HTTP-соединение.

Предпочитайте Streamable HTTP для новых решений.

## Подключение внешнего MCP-сервера через API

При вызове модели через OpenAI-совместимый API (базовый URL `https://ai.api.cloud.yandex.net/v1`) инструмент MCP описывается в поле `tools`:

```json
[
  {
    "server_label": "crm_lookup",
    "server_url": "<URL_MCP-сервера>",
    "type": "mcp",
    "metadata": {
      "description": "Поиск клиента в CRM по имени"
    }
  }
]
```

- `server_label` - метка сервера для идентификации инструмента.
- `server_url` - URL внешнего MCP-сервера.
- `type` - всегда `mcp`.
- `metadata.description` - описание инструмента для модели.

## Создание MCP-сервера с нуля в MCP Hub

Доступны три типа инструментов:

1. **Функция Yandex Cloud Functions** - запуск кода в обслуживаемой среде с автоматическим масштабированием.
2. **HTTPS-запрос** - обращение к внешним API: опишите имеющиеся API-методы, и они автоматически конвертируются для использования в агентах.
3. **Рабочий процесс Yandex Workflows** - сложные процессы из взаимодействующих инструментов и сервисов с собственной логикой управления и обработкой ошибок.

Также доступны шаблоны MCP-серверов от внешних партнёров Yandex Cloud (с аутентификацией).

## Типы MCP-вызовов модели

- `mcp_list_tools` - список инструментов MCP-сервера.
- `mcp_approval_request` - запрос на одобрение действия пользователем.
- `mcp_approval_response` - ответ на запрос: `approve` (boolean), `reason`.
- `mcp_call` - вызов инструмента: `server_label`, `name`, `arguments`, `output`, `error`, `status`, `approval_request_id`.

## Лимиты MCP

- MCP-серверов в облаке (квота): 30.
- Инструментов в одном сервере (квота): 150.
- Активных соединений в облаке на зону доступности: 500.

В документации MCP Hub упоминается до 50 инструментов на сервер - при проектировании ориентируйтесь на более консервативную оценку 50 и уточняйте актуальные значения в документации.

## Рекомендации по проектированию тулинга

1. **Минимальный набор инструментов** - подключайте только те, что реально нужны сценарию; каждый инструмент увеличивает стоимость и поверхность ошибок.
2. **Чёткие описания** - `description` и имена функций должны быть конкретными; неясные описания ведут к неправильным вызовам.
3. **Строгая схема** - всегда задавайте JSON Schema параметров и `strict: true` для критичных функций.
4. **Опасные действия через MCP** - используйте `mcp_approval_request` для действий с побочными эффектами (запись в CRM, переводы).
5. **Code Interpreter для данных** - задачи по анализу данных перекладывайте на Code Interpreter, а не на рассуждения модели.
6. **defer_loading** - при большом числе функций (десятки) включайте отложенную загрузку, чтобы не раздувать контекст.
