# RAG-решения: поисковые индексы и векторизация

Эта инструкция описывает, как проектировать RAG-решения (генерация ответов на основе проверенных данных) в Yandex AI Studio. Используйте её вместе со справочником моделей (`yandex_models_reference`) и инструкцией по Responses API (`agents_responses_api`).

## Архитектура AI Search

AI Search позволяет моделям генерировать ответы по двум типам источников:
- **Собственные данные** (документы, инструкции, FAQ) - инструмент File Search через поисковые индексы Vector Store, чанки и эмбеддинги.
- **Интернет по выбранным доменам** - инструмент Web Search.

Оба инструмента можно подключать одновременно; модель сама выбирает нужный по запросу, описаниям инструментов и промпту.

## Конвейер RAG

1. **Индексация** - AI Studio автоматически разбивает загруженные файлы на чанки (от нескольких строк до нескольких абзацев), токенизирует и сохраняет в поисковом индексе Vector Store. Для контроля качества можно самостоятельно разбить данные на чанки и загрузить их в формате JSONL (максимальная длина чанка - 8 000 символов).
2. **Формирование запроса** - модель формулирует поисковый запрос исходя из задачи и правил промпта.
3. **Поиск фрагментов** - инструмент возвращает релевантные чанки из индекса; они добавляются в контекст модели.
4. **Генерация ответа** - модель использует найденные фрагменты как факты.

## Источники данных

Вы можете загрузить документы базы знаний через:
- интерфейс AI Studio (Playground);
- Vector Store API;
- Files API.

После загрузки создайте поисковый индекс Vector Store. Чанки можно загрузить вручную в формате JSONL (максимальная длина - 8 000 символов), чтобы контролировать разбиение и избежать потери смысла.

## Инструмент File Search

В Responses API инструмент `file_search` имеет параметры:
- `vector_store_ids` - ID векторных хранилищ;
- `filters` - ComparisonFilter (`eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `in`, `nin`) или CompoundFilter (`and`/`or`) по атрибутам;
- `max_num_results` - максимум результатов (1-50);
- `ranking_options.ranker` - `auto` или `default-2024-11-15`;
- `ranking_options.score_threshold` - порог релевантности (0-1);
- `ranking_options.hybrid_search` - веса `embedding_weight` и `text_weight` (гибридный поиск по эмбеддингам и тексту).

## Эмбеддинги

- Количество входных токенов на векторизацию: 2 048.
- Размерность выходного вектора: 256.
- Квота: 10 запросов на векторизацию в секунду.
- Дообучение эмбеддингов поддерживается (LoRA).

## Лимиты файлов и поисковых индексов

- Максимум агентов: 1 000.
- Максимум загруженных файлов: 10 000, размер файла - 128 МБ.
- Файлов в одной загрузке: 100.
- Поисковых индексов: до 150 (квота), максимум 1 000 (лимит); файлов в индексе - 10 000.
- Одновременно запущенных операций индексации: 10.
- Максимальная длина пользовательского чанка: 8 000 символов.

## Выбор модели под RAG

- **YandexGPT Pro** - для RAG-сценариев: поиск по базам знаний и генерация ответов на основе найденного.
- **Alice AI LLM Flash** - быстрый агентский поиск по файлам и базам знаний, суммаризация.
- **DeepSeek V4 Flash** - при очень больших контекстах (1M токенов): можно передать объёмные найденные фрагменты целиком.
- При выборе учитывайте режимы работы: синхронный (оперативные ответы), асинхронный/фоновый (несрочные обработки), пакетный (массовая офлайн-обработка датасетов в Parquet).

## Рекомендации по качеству RAG

1. **Чанкинг** - для длинных документов целесообразно разбивать на чанки самостоятельно (JSONL) и контролировать их смысловую целостность.
2. **Атрибуты и фильтры** - используйте `filters` для сужения поиска (например, по типу документа), это повышает точность.
3. **Гибридный поиск** - для смешанных корпусов задавайте `hybrid_search` с весами.
4. **score_threshold** - поднимите порог, чтобы отсекать нерелевантные фрагменты.
5. **Промпт** - явно инструктируйте агента отвечать только на основе найденных фрагментов и не выдумывать факты.
6. **Проверка источников** - просите агента указывать file_id или название файла в ответе.
