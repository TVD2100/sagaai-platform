# Модели Yandex AI Studio (справочник для выбора)

Этот справочник - ваш основной ориентир при выборе моделей для решений на базе Yandex AI Studio. Данные собраны из официальной документации (`docs/YaAgentAI`) и конфигурации сервиса YandexAI (`services/yandex.json`). При разработке решения опирайтесь на справочник; при необходимости уточняйте детали в локальном каталоге документации или через веб-поиск.

## URI моделей

Модели базового инстанса доступны по URI вида `gpt://<идентификатор_каталога>/<имя_модели>` (текстовые и речевые) и `art://<идентификатор_каталога>/<имя_модели>` (генерация изображений). В поле `model` запроса Responses API / Chat Completions передавайте именно URI (с folder_id), а не голое имя.

Каждая версия модели сохраняет URI до вывода из эксплуатации; при значительных изменениях публикуется новая версия с новым URI. Автоматическое переключение версий не предусмотрено - при переходе на новую модель скорректируйте промпт и заново запросите квоты.

| Alice AI LLM Flash | `aliceai-llm-flash` | 64k | Быстрая, оптимизирована для агентских сценариев: работа с инструментами и вызов функций. Модерация, классификация обращений, диалог с клиентом, поиск по базам знаний, суммаризация. |

Модели Яндекса поддерживают около 20 языков и предназначены в первую очередь для эффективной работы с русским текстом. Собственный токенизатор экономит токены (пример: 501 символ русского текста ≈ 96 токенов у YandexGPT Pro против 139 у Qwen3 235B).

## Режимы работы моделей

- **Синхронный** - запрос → ответ в одном обращении. Responses API, Text Generation API, Chat Completions API. Для чат-ботов и оперативных запросов.
- **Потоковый** - частный случай синхронного, опция `stream`. Responses API, Realtime API, Chat Completions API. Для стриминга и «живого» общения.
- **Асинхронный** - отложенная обработка (минуты-часы), дешевле синхронного. Text Generation API, объект `Operation`. Для несрочных задач.
- **Фоновый** - обработка в фоне без ожидания, статус по идентификатору задачи. Responses API. Для долгих операций (большие файлы, сложные ответы).
- **Пакетный** - массовая обработка датасета, результат в Parquet. Text Generation API. Для крупных офлайн-обработок.

## Режим рассуждений (reasoning)

По умолчанию включён для моделей, которые его поддерживают; глубину модель выбирает автоматически. Управление: `reasoning_effort` (Completions API) или `reasoning` с полем `effort` (Responses API).

Поддерживаемые значения `reasoning.effort` (Responses API): `none`, `minimal`, `low`, `medium`, `high`, `xhigh`. По умолчанию - `medium`.

- `none` - рассуждения выключены.
- `minimal` / `low` - приоритет скорости и экономии токенов.
- `medium` - баланс между скоростью и точностью.
- `high` / `xhigh` - тщательное рассуждение.

### Допустимые значения reasoning_effort по моделям

Наборы значений, которые принимает каждая модель (`reasoning_effort` в Completions API / `reasoning.effort` в Responses API). Эти же наборы задаются в `reasoning_effort_options` модели в конфигурации сервиса (`services/yandex.json`, `defaults/services/yandex.json`).

| Модель | Допустимые значения |
| --- | --- |
| `yandexgpt-5-lite`, `yandexgpt-5-pro`, `yandexgpt-5.1` | `none`, `minimal`, `low`, `medium`, `high`, `xhigh` |
| `aliceai-llm`, `aliceai-llm-flash` | `none`, `minimal`, `low`, `medium`, `high` |
| `deepseek-v4-flash` | `none`, `minimal`, `low`, `medium`, `high`, `xhigh` |
| `qwen3-235b-a22b-fp8` | `low`, `medium`, `high` |
| `qwen3.6-35b-a3b` | `none`, `minimal`, `low`, `medium`, `high`, `xhigh` |
| `gpt-oss-120b`, `gpt-oss-20b` | `low`, `medium`, `high` |

## Формат ответа JSON

- `json_object` (или `response_format="json"`) - произвольная структура JSON. Дополнительно укажите требование JSON словами в промпте, чтобы модель не добавляла лишние токены.
- `json_schema` - строгий JSON по схеме (`properties`, `required`, `type: "object"`). Необходим при работе с внешними инструментами через вызов функций.

## Квоты и лимиты (основные)

- Синхронные генерации: 10 одновременных.
- Асинхронный режим: 10 запросов/с, 5 000 запросов/час.
- Генерация изображений: 500 запросов/мин, 5 000 в сутки.
- Классификация текста: 1 запрос/с.
- Векторизация: 10 запросов/с, 2 048 токенов на вход, вектор 256.
- Таймаут синхронного запроса: 20 минут.
- Хранение результатов асинхронных запросов: 3 суток.
