# Безопасность агентов и guardrails

Эта инструкция описывает механизмы безопасности агентных решений Yandex AI Studio: модерацию ответов (guardrails), словари, классификаторы, роли и управление доступом. Используется вместе со справочником моделей (`yandex_models_reference`) и инструкцией по Responses API (`agents_responses_api`).

## Модерация ответов (guardrails)

Модерация ответов (стадия Preview) проверяет запросы к генеративным моделям и ответы моделей на соответствие правилам:
- при нарушении в запросе запрос НЕ направляется в модель;
- при нарушении в ответе ответ НЕ отображается конечному пользователю;
- в обоих случаях пользователю возвращается сообщение, заданное правилом, без технической ошибки.

### Системное правило

- По умолчанию применяется ко всем собственным моделям Яндекса: классификатор в типовой конфигурации и системные словари.
- Для опенсорс-моделей системное правило по умолчанию отключено; можно применить вручную для инстансов.
- При применении пользовательского правила системное правило для инстанса отключается - ответственность переходит на пользователя.
- В моделях генерации изображений YandexART системное правило отключить нельзя.

### Текст системного сообщения при блокировке

```
Я не могу обсуждать эту тему. Давайте поговорим о чем-нибудь еще.
```

Максимальная длина пользовательского сообщения при блокировке - 1 000 символов.

### Настройка правил модерации

- Управляют правилами и словарями пользователи с ролью `ai.guardrails.editor` или выше на каталог.
- Для одного инстанса применимо только одно правило модерации.
- Изменения вступают в силу в течение нескольких минут.

## Классификатор в правиле модерации

Каждый запрос к модели и её ответ направляются в преднастроенный классификатор. Пороги срабатывания настраиваются отдельно для запросов пользователя и для ответов модели:

| Порог | Значение |
| --- | --- |
| `OFF` | Классификатор не применяется. |
| `LOW` | Блокируются только самые очевидные нарушения (например, грубые слова). |
| `MEDIUM` | Сбалансированный порог (по умолчанию). |
| `HIGH` | Блокирует больше контента, включая неоднозначные или спорные фразы. |
| `MAXIMUM` | Блокируется любой потенциально сомнительный контент. |

Сейчас при срабатывании классификатора контент можно только блокировать; планируется режим «только логировать».

## Словари в правилах модерации

Запросы и ответы проверяются на нежелательные фразы. Словари регистронезависимые; помимо фраз могут содержать регулярные выражения в формате re2.

Ограничения:
- К одному правилу можно привязать не более 50 словарей.
- Один словарь может быть привязан к нескольким правилам.
- Словарь содержит не более 1 000 фраз и не более 10 регулярных выражений.
- Длина одной фразы или регулярного выражения - не более 100 символов.

Системные словари можно использовать в пользовательских правилах, но их состав посмотреть нельзя. Сейчас срабатывание по словарю можно только блокировать; планируется режим «только логировать».

## Ответ модели при срабатывании правила

Поля ответа, указывающие на блокировку:
- `response.status` = `incomplete`;
- `response.incomplete_details.reason` = `content_filter`;
- `response.output` - текст сообщения, заданный правилом.

Важно: если запрос завершился срабатыванием модерации, его нельзя использовать в `previous_response_id`.

## Роли guardrails (ai.guardrails.*)

- `ai.guardrails.auditor` - просмотр метаданных правил.
- `ai.guardrails.viewer` - просмотр информации о правилах.
- `ai.guardrails.user` - применение правил модерации и просмотр метаданных.
- `ai.guardrails.editor` - создание, применение, изменение и удаление правил.
- `ai.guardrails.admin` - то же, что editor (включает её).

## Управление доступом (IAM)

- Все операции проверяются в Yandex Identity and Access Management (IAM); при отсутствии разрешений сервис возвращает ошибку.
- Роли назначаются на организацию, облако или каталог (наследуются вложенными ресурсами).
- Роль `ai.languageModels.user` (или выше) требуется для использования моделей.
- Роль `ai.models.user` (или выше) - для использования моделей, агентов и связанных сервисов.
- Роль `ai.editor` - для дообучения моделей.
- Вызов MCP-серверов и методов Responses API может быть ограничен политиками авторизации на уровне каталога/облака/организации (по сетям и IP-адресам).

## Рекомендации по защите агентов

1. **Не отключайте системное правило** без крайней необходимости - особенно для пользовательских сценариев.
2. **Пользовательские словари** - добавляйте доменно-специфические стоп-фразы (например, запрет обсуждать внутренние коммерческие условия).
3. **Пороги** - поднимайте до HIGH/MAXIMUM для сценариев с высокими требованиями к безопасности; оставляйте MEDIUM для обычных диалогов.
4. **Обработка content_filter** - при получении `status: incomplete` с `reason: content_filter` корректно завершайте диалоговый ход и не подставляйте запрос в `previous_response_id`.
5. **Принцип минимальных привилегий** - выдавайте роли по минимуму: `user` для эксплуатации, `editor` только для администрирования правил и дообучения.
6. **Аудит** - при изменениях и срабатываниях правил генерируются аудитные события; настройте их сбор для отладки.
7. **Входной фильтр до модели** - для чувствительных решений дополнительно фильтруйте входящие запросы на уровне приложения, не полагаясь только на guardrails.
