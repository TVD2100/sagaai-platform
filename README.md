# SagaAI - платформа для команды ИИ-сотрудников

**SagaAI - это платформа с открытым исходным кодом (source-available), на которой вы собираете и управляете собственной командой ИИ-сотрудников:** чат-ассистенты, автономные оркестраторы, базы знаний (RAG) и встроенный агент-разработчик DevAgent - в одном веб-интерфейсе, на вашем компьютере или сервере, с контролем над действиями агентов и защитой ваших данных. Лицензия - **PolyForm Noncommercial 1.0.0**: бесплатно для учёбы, личных проектов, образования и научных исследований, коммерческое использование - по отдельному договору.

Это не «ещё один чат-бот» и не «ещё один кодинг-агент». SagaAI объединяет персональных ассистентов, агентные платформы и кодинг-агентов в единой системе: сотрудники с разными ролями работают над задачами, опираются на ваши базы знаний, а агент-разработчик DevAgent редактирует код ваших проектов - с планом, утверждением, бэкапами и тестами.

## Кому подходит

Все сценарии ниже покрывает бесплатная некоммерческая лицензия - условия и полный список случаев в разделе [«Бесплатное использование»](#-бесплатное-использование).

### 🎓 Студентам и преподавателям

Учебные проекты, подготовка лекций и методических материалов, разбор сложных тем с ассистентом, проверка и рецензирование текстов, тренажёр по предмету на собственных конспектах. Базы знаний держат учебники и методички локально: агент отвечает по вашим материалам, а не по общим данным модели. Работает без API-ключей на лексическом поиске.

### 🔬 Исследователям и научным группам

Сбор и структурирование литературы, извлечение данных из PDF и таблиц, обработка результатов экспериментов, воспроизводимые опыты с ИИ-агентами. DevAgent помогает с кодом для обработки и анализа данных - с бэкапами, тестами и полным откатом.

### 🏛️ Некоммерческим организациям

Благотворительные фонды, госучреждения, организации здравоохранения и охраны окружающей среды: обработка обращений, работа с документами, подготовка отчётов и заявок, внутренняя база знаний по программам и регламентам.

### 🏡 Личным и хобби-проектам

Домашние проекты, любительская разработка, личные исследования и эксперименты, обучение новым инструментам. Можно собрать команду помощников под свои задачи, подключить базы знаний по интересам и вести проекты в DevAgent - без коммерческого применения.

### 👥 Сотрудники под конкретные роли

Ключевая идея платформы - не один универсальный чат-бот, а **команда специализированных ИИ-сотрудников**. Каждый сотрудник настраивается под узкую задачу без единой строки кода: роль и системный промпт, модель, набор инструментов, инструкции, навыки, свои базы знаний и подключения. Дальше вы просто переключаетесь между сотрудниками в сайдбаре или ставите задачу тому, чья специализация подходит.

| Сотрудник | Чем занимается |

| 📣 **Маркетолог** | Контент-план, тексты для сайта и рассылок, разбор конкурентов по вашей базе знаний, гипотезы и описания сегментов |
| 💰 **Финансист** | Разбор таблиц и выгрузок (xlsx), расчёты, бюджеты, сверка статей расходов, пояснения к отчётам |
| 🔬 **Исследователь** | Обзор источников и литературы, сравнение подходов, сборка фактов с опорой на базы знаний и веб-поиск |
| 🗂️ **Секретарь** | Протоколы встреч, резюме переписки, планирование, черновики писем и поручений |
| 🧭 **Аналитик** | Обработка данных, сводки и выводы, подготовка регулярных отчётов по шаблону |

## Возможности

Каждая возможность платформы обслуживает главную идею - **команда ИИ-сотрудников под вашим контролем**.

### 💬 Чат с ИИ

- Чат с поддержкой OpenAI-совместимых API (YandexAI, DeepSeek) и GigaChat; поддержка веб-поиска от Yandex AI и Deepseek.
- Прикрепление файлов: текст, PDF, офисные форматы (docx, pptx, xlsx) с автоматическим извлечением содержимого.
- Ответы в Markdown с подсветкой синтаксиса и кнопкой копирования.

### 👥 Сотрудники (оркестраторы)

- Каждый сотрудник - автономный агент со своим системным промптом, моделью, эконом-режимом, инструментами, инструкциями, функциями, навыками, базами знаний и подключениями.
- **Модели.** Единая основная модель для всех шагов; дополнительно можно назначить модели распознавания и генерации изображений. У встроенного DevAgent поставляемые дефолты: DeepSeek `deepseek-flash` как основная модель (уровень рассуждений `xhigh`) и как модель распознавания изображений, генерация изображений не назначена. Назначенные модели используются инструментами `analyze_image` / `generate_image`: сотрудник читает изображения (вложения диалога или файлы проекта; YandexAI - `qwen3.6-35b-a3b` / `deepseek-v4.1-flash`, DeepSeek - `deepseek-flash`) и может сгенерировать новое (синхронный Images API YandexAI, модель `aliceai-image-art-3.0`) - результат сохраняется файлом и показывается в чате с кнопкой скачивания.
- **Загрузка страниц.** Необязательная модель загрузки: в списке только провайдеры с поддержкой Search/Fetch API (DeepSeek - модели `deepseek-flash` и `deepseek-v4-pro`). Рядом - чек-бокс «Использовать Selenium»: страница открывается в headless-браузере, её видимый текст основная модель переводит в Markdown (нужен пакет `selenium` и браузерный драйвер; при их отсутствии инструмент вернёт подсказку об установке). Пока чек-бокс включён, селекторы модели загрузки скрыты - конвертацию делает основная модель; сохранённая пара возвращается после снятия флажка.
- **Инструмент `url_fetch`.** При назначенной модели или включённом Selenium у сотрудника появляется инструмент `url_fetch` - загрузка одной веб-страницы как чистого Markdown-текста; ссылка на PDF скачивается и разбирается по страницам, остальное идёт через Search/Fetch API или браузер. URL валидируется (http/https, без логина и пароля, приватные и локальные адреса запрещены), содержимое санитизируется и помечается как недоверенные данные, длина ограничена 30 000 символов. Снятие обоих источников убирает инструмент; прежнее имя `page_fetch` работает как алиас.
- **Делегирование.** `spawn_agent` запускает другого сотрудника (в том числе параллельно - независимые запуски выполняются веером, а лента группирует события по запуску), `invoke_assistant` - один вызов помощника без цикла инструментов. В задании субагенту передаются абсолютные пути рабочей папки родителя и его файлов диалога, поэтому вложения доступны без пересылки; документ уходит помощнику файлом в `context_files` и читается целиком за один вызов. Кто кому может делегировать и сколько запусков разрешено, задаётся на вкладке «Делегирование»: чек-боксы сотрудников и помощников плюс шесть лимитов (глубина дерева, одновременные запуски, шаги и суммарное число запусков ребёнка, таймаут, потолок токенов). Остановка диалога отменяет и дочерние запуски. По умолчанию делегирование разрешено на один уровень вглубь, вызовы помощников закрыты до явного разрешения.
- **Документы.** `read_thread_file` открывает вложения диалога, `read_document` - файл в рабочей папке по абсолютному пути (окно строк для больших файлов). Поддерживаются PDF, DOCX, DOC, PPTX, XLSX, XLS, RTF, ODT, HTML и plain text; текст и исходники читаются напрямую, поэтому `run_code` остаётся средством последней очереди.
- **Системные функции включаются и выключаются чекбоксами** на вкладке «Функции»; отключённый инструмент реально блокируется диспетчером.
- В системный промпт каждого сотрудника автоматически добавляется каталог доступных инструментов (`## Available tools`) с правилами вызова; независимые вызовы разрешено объединять в один батч (с условиями независимости).
- Сотрудники ищут по истории диалогов: `search_in_threads` (по умолчанию - текущий диалог, без предварительных списков; явный `thread_id`, охват по оркестратору или всем диалогам, период), `list_threads` и `read_thread`. DevAgent видит все диалоги, остальные сотрудники - только свои.
- Правки системного промпта встроенного сотрудника (DevAgent) сохраняются между перезапусками; вернуть поставляемый промпт можно кнопкой сброса на вкладке «Промпт».
- DevAgent - встроенный (неудаляемый) оркестратор, всегда доступен.
- Секция «Сотрудники» в сайдбаре: первые 5 всегда видны, остальные - в свёрнутом блоке «Все (N)»; поиск показывается только при количестве сотрудников больше пяти. Порядок - по времени последнего диалога (новые и недавно использованные сверху).
- В ленте чата у каждого завершённого текстового ответа сотрудника есть панель выгрузки/копирования (📥 MD / 📥 TXT и Copy MD / Copy TXT); ответы с вызовами инструментов панели не получают.

### 🧩 Помощники

- Создание, редактирование и удаление помощников (системных промптов) с привязкой файлов и подбором модели под сложность задачи.
- Assistant Creator - встроенный мета-инструмент: генерирует качественный системный промпт по описанию роли.
- Секция «Помощники» в сайдбаре: первые 5 всегда видны, остальные - в свёрнутом блоке «Все (N)»; поиск показывается только при количестве помощников больше пяти.

### 🔧 DevAgent - встроенный агент-разработчик

- Редактирование кода с утверждением изменений: каждое изменение предлагается и применяется контролируемо.
- Полностью автономный режим по вашему выбору. При готовом плане DevAgent спросит, следовать ли ему в точности или сначала проанализировать код; при подробном ТЗ - действовать ли без согласования. План всё равно составляется, но фаза утверждения пропускается и исполнение начинается сразу.
- Версионирование файлов (бэкапы), снапшоты проекта и полный откат.
- Регламентированный пайплайн тестирования: юнит-тесты, регрессия, сценарные тесты, саморевью.
- Внешняя память задач (`TASK_STATE.md`): план, прогресс, журналы анализа и открытых вопросов - для многоэтапных работ.
- Защита от path traversal (инструменты не выходят за пределы рабочей папки), санитизация и разметка недоверенных данных, эвристическая защита от prompt-injection.
- Работа с любым проектом: DevAgent строит карту проекта (`PROJECT_MAP.md`) и ведёт документацию (`AGENT.md` - ключевая информация для агентов, архитектура, changelog).
- Изоляция рабочей папки: новый диалог начинается без папки («папка не выбрана»), активная папка привязана к диалогу и восстанавливается при его открытии; меню недавних папок у каждого сотрудника своё.
- Блок «Выбор папки» в чате: «Авто», до 10 недавних папок и нативный выбор папки на компьютере. Выбранная папка применяется автоматически при отправке сообщения (агент не тратит на это шаг), после чего селектор возвращается в «Авто», а активный путь виден под полем.
- Авто-прокрутка ленты чата: пока агент работает, лента следует за новым выводом; прокрутка вверх ставит слежение на паузу, возврат к низу - возобновляет; отправка сообщения прокручивает вниз.
- Загрузка файлов прямо в поле ввода чата: иконка-скрепка с подсказкой, без отдельного блока и подписи; файлы уходят вместе с текстом одной отправкой.

### 📚 Базы знаний (RAG)

- Локальные базы знаний с тремя режимами поиска: **bm25** (собственный полезависимый лексический индекс BM25F, без API-ключей, режим по умолчанию), **vector** (семантический поиск по эмбеддингам) и **hybrid** (объединение через RRF); загрузка документов, автоматическая индексация (чанкинг + BM25; эмбеддинги - в режимах vector/hybrid). В режиме bm25 тело чанка и его контекстная шапка (продукт, заголовок, раздел) индексируются как отдельные поля: термин из шапки помогает найти нужный продукт или раздел и не «забивает» ранжирование.
- Страница «Хранилище»: создание баз, файлы, индексация, тестовый поиск и переключение режима поиска. DevAgent и сотрудники обращаются к базам напрямую; результаты поиска несут идентификаторы чанков, а инструмент добора (`rag_get_chunks`) возвращает соседние фрагменты для восстановления полного контекста.

### 🧠 Библиотека навыков

- Стандартизированные пакеты инструкций и скриптов для сотрудников и DevAgent.
- Создание навыков по запросу на естественном языке и адаптация навыков из других экосистем ИИ-агентов.

### 🔗 Коннекторы

- Подключение внешних сервисов (GitHub, SSH, MCP) с хранением токенов и ключей в защищённом виде.
- Создание подключения через DevAgent прямо в чате: сначала черновик без секретов, затем заполнение учётных данных на странице «Коннекторы». У каждого подключения есть файл памяти агента (заметки о сервере и лимитах - без секретов).
- Готовые пресеты MCP-серверов без секретов на отдельной вкладке «MCP-серверы»: плитка с иконкой «ВкусВилл» открывает форму подключения с уже заполненной конфигурацией сервера, где остаётся ввести токен; рядом - плитка «Свой MCP-сервер» для любого stdio/http-сервера. Работа с GitHub идёт через отдельное подключение «GitHub» (`github_rest`), которому нужен обычный Personal Access Token. Поддерживаются оба транспорта MCP - локальный stdio и удалённый HTTP.
- Страница «Коннекторы» построена как «список ↔ форма»: клик по плитке сервиса или пресета открывает форму на той же странице, и подключение появляется в списке только после нажатия «Создать» - сразу рабочее, с введёнными учётными данными. «Отмена» и «← Назад» возвращают к списку, ничего не создавая; редактирование открывается такой же формой на всю страницу. Три вкладки - «Общие сервисы» (плитки GitHub/SSH), «MCP-серверы» и «Подключения» (карточки всех сохранённых подключений с иконкой сервиса, состоянием учётных данных, проверкой, редактированием и удалением); выбранная вкладка не сбрасывается при кликах и сохранениях.

### 📎 Файлы в диалогах

- В диалоги оркестраторов загружаются файлы любого формата (до 100 МиБ на файл); агент сам решает, когда и как извлекать содержимое.

### 🔄 Обновления платформы

- Встроенный конвейер обновлений через публичный GitHub-репозиторий без токена: проверка, выборочная установка (файлы - по отдельности, пакеты кода - целиком), просмотр и откат.
- Применение только при холодном старте, каждый файл бэкапится, запись атомарная, сбой откатывается.

### 📊 Статистика

- Страница «Статистика»: расход токенов по периодам, поставщикам и моделям на основе диалогов помощников и сотрудников.

### 🛡️ Защита данных

- Страница «Доступы»: вход по паролю, интервал повторного запроса; во время выполнения задачи оркестратором авторизация не запрашивается.
- TLS-верификация включена по умолчанию; API-ключи хранятся в защищённом виде (или задаются через переменные окружения и не сохраняются в БД); секреты не отображаются в интерфейсе.

### 🎨 Интерфейс

- Темы оформления: светлая, тёмная, системная. Интерфейс на русском, английском и китайском языках.
- Единая «История» всех диалогов с фильтрами и поиском.

## 📦 Быстрый старт

### ✅ Требования

- **Python 3.12 или новее.** Проверьте командой `python --version` (на Windows также подойдёт `py --version`). Если Python не установлен, скачайте его с [python.org](https://www.python.org/downloads/); при установке на Windows отметьте пункт **«Add Python to PATH»**.
- **Зависимости из `requirements.txt`** (включая **Streamlit 1.66.0 или новее**). При первом запуске приложение само проверяет установленные библиотеки и их версии: если чего-то не хватает или версия устарела, появится предупреждение с командой `pip install -r requirements.txt` (или `pip install -U <пакет>`) - выполните её для стабильной работы платформы.

### 🪟 Windows (WSL не требуется)

1. **Скачайте репозиторий (Git не обязателен).** Страница репозитория → **Code → Download ZIP** → распакуйте архив в удобную папку. Либо клонируйте: `git clone https://github.com/TVD2100/sagaai-platform SagaAI`.

2. **Откройте терминал в папке проекта.** Зайдите в папку, затем Shift + правая кнопка мыши по пустому месту → «Открыть окно PowerShell здесь».

3. **Установите зависимости:** `pip install -r requirements.txt`.

4. **Запустите приложение:** `streamlit run app.py` и откройте [http://localhost:8501](http://localhost:8501/).

### 🐧 macOS / Linux

1. **Клонируйте репозиторий:** `git clone https://github.com/TVD2100/sagaai-platform SagaAI`, затем `cd SagaAI`.

2. **Установите зависимости:** `pip install -r requirements.txt`.

3. **Запустите приложение:** `streamlit run app.py` и откройте [http://localhost:8501](http://localhost:8501/).

4. **Задайте API-ключи** нужных AI-сервисов на странице «Настройки» - после этого можно создавать помощников, сотрудников и базы знаний.

> 💡 Если команда `streamlit` не найдена, запускайте через модуль Python: `python -m streamlit run app.py`.

## 🔐 Настройка безопасности

### Включение защиты паролем

**Способ 1 - страница «Доступы» (рекомендуется):** в боковом меню «🔐 Доступы» включите «Доступ по паролю», задайте пароль и подтверждение, настройте интервал повторного запроса и нажмите «Сохранить». Пароль хранится в БД в зашифрованном виде (Fernet).

**Способ 2 - переменная окружения** `SAGAAI_AUTH_PASSWORD`.

После включения интерфейс показывает форму входа. Пароль из формы имеет приоритет перед переменной окружения; при выключенном переключателе на странице «Доступы» пароль не запрашивается.

### TLS-верификация

По умолчанию все HTTPS-запросы к AI-сервисам проверяют сертификаты (`verify=True`). Отключать проверку не рекомендуется: без неё возможна MITM-атака с перехватом API-ключей и содержимого диалогов. При необходимости (корпоративный прокси, самоподписанный CA) есть два штатных способа.

**Свой CA-бандл.** Переменная `SAGAAI_GIGACHAT_CA_BUNDLE` задаёт путь к PEM-файлу с корневым сертификатом для запросов к GigaChat. По умолчанию используется встроенный `certs/russian_trusted_root_ca.pem` - Russian Trusted Root CA, которым подписаны эндпоинты GigaChat (этого корня нет в стандартном бандле `certifi`).

```
export SAGAAI_GIGACHAT_CA_BUNDLE=/path/to/corporate_ca.pem
streamlit run app.py
```

**Полное отключение проверки (крайняя мера).** Переменная `SAGAAI_VERIFY_TLS=false` отключает TLS-верификацию для всех запросов к AI-сервисам. Используйте только в доверенной сети.

## 🛠 Для разработчиков

| Пакет | Назначение |
| --- | --- |
| `app.py` | Точка входа Streamlit |
| `core/` | Бизнес-логика (API, файлы, помощники, оркестраторы, RAG, аутентификация, криптография, обновления) без зависимостей от Streamlit |
| `ui/` | Страницы интерфейса (чат, сотрудники, хранилище RAG, статистика, коннекторы, библиотека навыков) |
| `storage/` | SQLAlchemy ORM-модели и репозиторий для SQLite |
| `dev_agent/` | Агентный цикл DevAgent: безопасный писатель, инструменты, подбор моделей, внешняя память задач |
| `defaults/` | Канонические копии: промпты оркестраторов, инструкции, пресеты, локализации, RAG-базы |
| `tests/` | Полный набор тестов (pytest), включая сценарные (`tests/scenarios/` и `tests/smoke/`) |
| `langs/` | Переводы интерфейса (ru, en, zh-CN) |

**Технологии:** Python 3.12+ · Streamlit · SQLite через SQLAlchemy · RAG-индекс (BM25 на SQLite; векторный поиск - косинусное сходство, эмбеддинги Yandex Embeddings API) · `cryptography` · pytest.

**AI-провайдеры:** OpenAI-совместимые API (YandexAI, DeepSeek), GigaChat; веб-поиск DeepSeek - через Anthropic-совместимый endpoint (модель deepseek-flash).

**Обновления:** версии и хеши всех поставляемых файлов ведёт манифест `file_versions.json`; конвейер обновлений доставляет их пользователям через публичный GitHub-репозиторий без токена. Обновления применяются при холодном старте, с бэкапом и откатом при сбое.

**Тесты:** `python3 -m pytest` - полный регрессионный набор.
