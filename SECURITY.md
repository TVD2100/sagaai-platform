# Политика безопасности SagaAI

Документ описывает, какие версии получают исправления безопасности, как
сообщить об уязвимости, на чём держится доверие к обновлениям и что именно
гарантирует песочница, а что остаётся за её границей.

## Поддерживаемые версии

Исправления безопасности выпускаются для последней опубликованной версии
линии 2.x. Более ранние версии не получают отдельных выпусков: обновление до
текущей версии - штатный способ закрыть найденную проблему. Линия 1.x снята с
поддержки.

## Как сообщить об уязвимости

**Не открывайте публичный issue.** Уязвимость, описанная в открытом трекере,
становится известна раньше, чем выйдет исправление.

Приватный канал - GitHub Security Advisories:

    https://github.com/TVD2100/sagaai-platform/security/advisories/new

Форма требует учётной записи GitHub - бесплатной. Если её нет, откройте
публичный issue без подробностей («прошу приватный канал для сообщения об
уязвимости») и дождитесь ответа: описание проблемы уйдёт в приватный канал,
а не в трекер.

Сообщение остаётся видимым только владельцу репозитория и вам. Подтверждение
получения приходит в течение пяти рабочих дней; дальше согласуются сроки
исправления и порядок раскрытия. О найденной проблеме имеет смысл сообщать,
если затронут хотя бы один из контуров, перечисленных ниже.

### Что включить в сообщение

- версия платформы (`core/version.py` или страница «Обновления»), ОС и способ
  запуска (Streamlit, HTTP API, консоль `sagaai`);
- последовательность действий, приводящая к проблеме, и что наблюдается
  вместо ожидаемого;
- чем подтверждается эффект: вывод инструмента, запись в журнале, файл;
- оценка последствий: утечка данных, выполнение кода, повышение прав,
  подмена обновления;
- по возможности - предложение по исправлению.

Не прикладывайте настоящие API-ключи, пароли и содержимое чужих диалогов.

## Доверие к обновлениям

Установка доверяет только тому манифесту обновления, чья отделённая подпись
сходится с ключом, который уже лежит на диске. Ключ никогда не загружается из
того же канала, что и манифест: подпись, доставленная рядом с подписанным
файлом, не доказывает ничего.

**Схема.** Ed25519. Публикатор пишет `file_versions.json.sig` рядом с
манифестом; подпись покрывает ровно те байты, которые скачивает установка,
без повторной сериализации JSON.

**Идентификатор ключа.** `key_id` выводится из самого публичного ключа (первые
восемь байт SHA-256 его DER-кодировки). Ключ не может назваться чужим
идентификатором, а неизвестный `key_id` - это отказ, а не пропуск.

**Хранилище ключей.** Папка `keys/` внутри установки. Читаются файлы `*.pem` и
`*.pub`; несколько ключей могут лежать одновременно, что и делает возможной
ротацию без обрыва обновлений у уже установленных копий. Переопределить папку
можно настройкой `marketplace.signature_keyring` или переменной окружения
`SAGAII_SIGNATURE_KEYRING` - это нужно приватному зеркалу.

**Политика каналов.**

| Канал | Неподписанный манифест |
| --- | --- |
| `stable` | отказ, обновление не устанавливается |
| `main`, `raw`, `dev`, `beta` | принимается с предупреждением, факт пишется в журнал |

Настройка `marketplace.require_signature = true` распространяет отказ на любой
канал, включая разработческий. Политика применяется одинаково к манифесту
обновлений и к каталогу маркетплейса.

**Приватный ключ.** Хранится вне репозитория, в домашнем каталоге публикатора
(`~/.sagaai/ed25519.pem`, права `0600`), либо передаётся через переменную
`SAGAII_SIGNING_KEY` (PEM-текст или путь). Резервная копия ключа обязательна:
установки доверяют опубликованному ключу, и его утрата означает, что новые
подписи делать нечем. Порядок ротации описан в `keys/README.md`.

## Защита доступа

Интерфейс закрывается паролем на странице «Доступы» либо переменной
`SAGAAI_AUTH_PASSWORD`. Пароль хранится в базе в зашифрованном виде (Fernet,
ключ `~/.sagaai/encryption_key`). HTTP API использует bearer-токены, которые
создаются на той же странице и хранятся в базе.

По умолчанию HTTPS-запросы к AI-сервисам проверяют сертификаты. Переменная
`SAGAAI_VERIFY_TLS=false` отключает проверку полностью - это допустимо только в
доверенной сети, поскольку снимает защиту от перехвата ключей и содержимого
диалогов.

## Песочница исполнения кода

`run_code` и `run_test` не запускают программу напрямую: запрос называет
профиль, политика выбирает сильнейшего провайдера, которого машина реально
может предоставить, и **отказывает в запуске**, если заявленная изоляция
недостижима. Молчаливого ослабления гарантии не происходит: непонятное имя
профиля не откатывается к разрешающему по умолчанию.

| Профиль | Изоляция | Сеть | Запись |
| --- | --- | --- | --- |
| `read_only` | ОС | нет | нет |
| `workspace_write` | ОС | нет | рабочая папка |
| `network` | ОС | да | рабочая папка, общий `/tmp` |
| `legacy_process` | нет | да | права процесса платформы |
| `off` | нет | да | права процесса платформы |

Профиль `off` - осознанный выбор пользователя (снятый флажок «Песочница»); он
не подменяется более сильной изоляцией на машине, где та доступна. Профили
`legacy_process` и `off` сохраняют пределы ресурсов и собранное окружение, но
не дают изоляции ОС.

**Что песочница ограничивает.** Запись за пределы разрешённых корней,
сетевые соединения там, где профиль их запрещает, объём памяти, время
работы, число процессов и размер вывода. Запись в `.git` разрешена, чтобы
работал документированный цикл публикации, но `hooks`, `config` и хранилище
объектов закрыты: команда `git`, запущенная после правки, не выполнит
подложенный код.

**Что песочница не делает.** Она не решает, заслуживает ли код доверия, и не
является границей против злоумышленника с правами самой платформы. Профили
`legacy_process` и `off` не изолируют процесс. Профиль `network` разрешает
исходящие соединения. Отдельно: защита от prompt-injection снижает риск того,
что модель примет инструкцию из прочитанных данных за команду пользователя, но
не устраняет его полностью - содержимое файлов, веб-страниц и результатов
инструментов остаётся недоверенным.

## Составляющие установки

| Путь | Содержимое |
| --- | --- |
| `~/.sagaai/encryption_key` | Ключ шифрования пароля доступа и секретов подключений |
| `~/.sagaai/ed25519.pem` | Приватный ключ подписи релизов (только у публикатора) |
| `~/.sagaai/marketplace.pem` | Приватный ключ каталога маркетплейса (только у публикатора) |
| `keys/` | Публичные ключи доверия; единственное, что публикуется |
| `sagaai.db`, `devagent.db` | Диалоги, настройки, журналы |
| `services/*.json` | Параметры AI-сервисов без секретов |

Секреты подключений (токены GitHub, SSH-ключи, пароли MCP) хранятся
зашифрованными в базе и не попадают в репозиторий, манифест обновлений и
журналы. Резервная копия установки должна включать `~/.sagaai/encryption_key`:
без него сохранённые секреты не восстановить.

## Раскрытие

После выпуска исправления уязвимость описывается в GitHub Security Advisory с
указанием затронутых версий, последствий и способа обновления. Автор сообщения
указывается по желанию.
